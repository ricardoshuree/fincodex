Parte 1 — Antes de começar

Premissas de acesso

Confirme os itens abaixo antes de iniciar a extração. A maioria dos bloqueios na AWS é de permissão — resolver isso primeiro evita retrabalho.

1
Identifique o tipo de conta e estrutura organizacional
Tipo de contaComo identificarImpacto no billing
StandaloneConta independente, sem OrganizationsExport disponível diretamente na conta
Management Account (payer)Conta raiz de uma OrganizationExporta billing consolidado de todas as contas — recomendado
Member AccountConta gerida por uma Management AccountExporta apenas seus próprios custos
GovCloud / ChinaRegiões isoladasExportação FOCUS não disponível
Acesse o AWS Console → clique no nome da conta (canto superior direito). Se aparecer "Organization" e "Management account", você está na conta pagadora. Recomendado: sempre exportar a partir da Management Account.
2
Acesso IAM ao Billing habilitado

Este é o bloqueio mais comum e invisível na AWS. Por padrão, apenas o usuário root tem acesso ao console de Billing — mesmo usuários IAM com AdministratorAccess ficam bloqueados até o root liberar.

  1. Acesse o Console com a conta root
  2. Canto superior direito → nome da conta → "Account"
  3. Em "IAM user and role access to Billing information", verifique se está "Activated"
Se estiver "Deactivated": apenas o root pode alterar. Acione o responsável pela conta root.
3
Permissões IAM para Data Exports
NamespacePermissãoPara quê
bcm-data-exportsCreateExportCriar a exportação FOCUS
bcm-data-exportsListExports, GetExportVer exportações existentes
bcm-data-exportsListTables, GetTableListar tabelas disponíveis
curPutReportDefinitionObrigatório para criação via Data Exports
s3PutObject, PutBucketPolicyConfigurar o bucket de destino

Políticas gerenciadas que já cobrem o necessário: AdministratorAccess (requer item 2 ativo), Billing (inclui Data Exports), ou AWSBillingReadOnlyAccess (apenas leitura, não cria exports).

Verifique em IAM Console → Users → seu usuário → aba Permissions.

4
Acesso ao Amazon S3 (bucket de destino)

O bucket S3 deve pertencer à mesma conta que cria a exportação — não é possível entregar em bucket de outra conta.

Bucket novo: requer s3:CreateBucket — o console pode criar automaticamente.
Bucket existente: requer s3:PutBucketPolicy — a policy atual será substituída pela gerada pelo Data Exports.

Verifique em S3 Console → bucket → aba Permissions se há permissão de escrita e edição de policy.
5
Restrições de SCP (apenas AWS Organizations)

Se a conta faz parte de uma Organization, Service Control Policies (SCPs) aplicadas pela Management Account podem bloquear ações de billing/S3 mesmo com permissões IAM corretas.

Erros típicos: You don't have permission to access billing information ou explicit deny.

Nestes casos, acione o administrador da Management Account — o administrador IAM local não controla SCPs.
6
Disponibilidade do FOCUS no seu ambiente
CondiçãoSuporta FOCUS
Standalone / Management / Member AccountSim
GovCloud (us-gov-*)Não
China (cn-*)Não

O console de Data Exports fica na região us-east-1, mas os dados cobrem todas as regiões da conta.

Self-check antes de prosseguir
Identifico o tipo de conta AWS (standalone, Management ou Member)
O acesso IAM ao Billing está habilitado (ativado pelo root)
Tenho bcm-data-exports:CreateExport e cur:PutReportDefinition
Tenho acesso de escrita a um bucket S3 na mesma conta
Minha conta não está em região GovCloud ou China

Parte 2 — Manuseio da interface

Passo a passo de extração

Com as premissas confirmadas, siga os passos abaixo no AWS Console para configurar a exportação no formato FOCUS 1.0 with AWS columns.

1

Acesse o Billing and Cost Management

Faça login em console.aws.amazon.com e busque "Billing" na barra de pesquisa superior → selecione Billing and Cost Management.

Erro "You don't have permission to access billing information"? Volte à premissa 2 — acesso IAM ao billing.
2

Navegue até Data Exports

No menu lateral, clique em Data Exports → botão Create export no topo.

Não aparece "Data Exports"? Confirme que o console está na região us-east-1. Se persistir, é falta da permissão bcm-data-exports:ListExports.

Não confunda com "Legacy exports → Cost and Usage Reports" — isso é o CUR antigo, não FOCUS.

3

Selecione o tipo de export

Em "Export type", selecione Standard data export → Next.

4

Configure nome e tabela de dados

Export name: nome descritivo, até 128 caracteres (ex: focus-export-mensal).

Table: selecione exatamente FOCUS 1.0 with AWS columns.

Existem outras tabelas (CUR 2.0, Carbon emissions) — confirme que selecionou a tabela FOCUS. Não há seleção de colunas: todas são incluídas automaticamente.
5

Configure opções de entrega

Refresh cadence: apenas "Daily" está disponível.

File versioning: "Overwrite" (recomendado, economiza espaço) ou "Create new file".

Formato:

FormatoExtensãoRecomendação
gzip – text/csv.csv.gzRecomendado — compatível com pipeline finops-focus
Parquet.parquetAlternativa para volumes muito grandes
6

Configure o bucket S3 de destino

Em "S3 bucket", selecione This account (obrigatório).

Bucket novo: nome único globalmente, defina a região (recomendado us-east-1), revise a bucket policy e confirme.

Bucket existente: selecione na lista — atenção, a policy atual será substituída.

S3 path prefix: ex. aws/focus ou billing/focus-exports.

7

Revise e crie a exportação

Confirme: Data table = FOCUS 1.0 with AWS columns, Compression correto, bucket correto → Create.

O status aparecerá como "Healthy" ou "Pending". Pode levar até 24h para o primeiro arquivo ser entregue.
8

Execute manualmente (opcional)

Para não esperar o ciclo diário: abra a exportação criada → Run export → aguarde status "Running" → "Healthy".

9

Exporte dados históricos (backfill)

Selecione a exportação → Export date range → defina o período → Run.

Backfill via console suporta até 13 meses. Para períodos mais antigos, é necessário usar a API.
10

Localize e baixe o arquivo gerado

No S3 Console, a estrutura segue:

[bucket]/[prefixo]/[export-name]/data/
  └── BILLING_PERIOD=YYYY-MM/
        └── arquivo.csv.gz (ou .parquet)

Ou via AWS CLI:

aws s3 ls s3://[bucket]/[prefixo]/[export]/data/BILLING_PERIOD=YYYY-MM/
aws s3 cp s3://[bucket]/[prefixo]/[export]/data/BILLING_PERIOD=YYYY-MM/ . --recursive
11

Valide o arquivo recebido

  • Extensão .csv.gz ou .parquet, tamanho maior que 0 KB
  • Cabeçalho contém: BillingPeriodStart, ChargePeriodStart, EffectiveCost, ProviderName, ChargeDescription
  • ProviderName = Amazon Web Services

Verificar cabeçalho sem abrir o arquivo inteiro (Linux/macOS):

zcat arquivo.csv.gz | head -1

Windows (PowerShell, após descompactar):

Get-Content "arquivo.csv" -TotalCount 1
Parte 3 — Suporte

Problemas frequentes

Bloqueios mais comuns e como resolvê-los.

Não consigo acessar "Billing and Cost Management" ▾
Acesso IAM ao billing desabilitado. O root da conta deve habilitar "IAM user and role access to Billing" nas configurações da conta.
O menu "Data Exports" não aparece ▾
Console em região diferente de us-east-1, ou falta de permissão. Troque a região; se persistir, solicite bcm-data-exports:ListExports.
A tabela "FOCUS 1.0 with AWS columns" não aparece ▾
Permissão insuficiente ou conta em região não suportada. Verifique permissões IAM e confirme que não está em GovCloud/China.
Erro "not authorized to perform bcm-data-exports:CreateExport" ▾
Falta de permissão IAM. Solicite ao administrador a política Billing ou as permissões mínimas da premissa 3.
Erro ao configurar bucket S3: "not authorized to set bucket policy" ▾
Falta de s3:PutBucketPolicy. Solicite ao administrador S3 que aplique a policy manualmente.
Export criado mas o arquivo nunca chega no S3 ▾
Bucket policy incorreta ou bucket em outra conta. Verifique se a policy foi aplicada corretamente e se o bucket pertence à mesma conta.
Arquivo gerado sem campos FOCUS (schema diferente) ▾
Tabela CUR 2.0 ou legacy selecionada por engano. Exclua o export e recrie selecionando "FOCUS 1.0 with AWS columns".
Member Account não vê dados de outras contas ▾
Limitação de design — member vê apenas seus próprios custos. Solicite à Management Account que crie o export consolidado.
Parte 4 — Finalização

O que enviar à FinCodex

Após concluir a extração, envie os itens abaixo para o time responsável pela análise:

  • Arquivo(s) .csv.gz ou .parquet — um por mês exportado
  • Período coberto (ex: BILLING_PERIOD=2025-01 a 2025-06)
  • Tipo de conta: Standalone / Management Account / Member Account
  • Nome do bucket e prefixo S3
  • Região do bucket (ex: us-east-1)

Parte 2 — Manuseio da interface

Passo a passo de extração

Com as premissas confirmadas, siga os passos abaixo no portal Azure para configurar a exportação com o template Cost and usage details (FOCUS).

1

Acesse o Cost Management no portal Azure

Faça login em portal.azure.com, pesquise "Cost Management" → selecione Cost Management + Billing → menu lateral → Cost Management.

Se houver múltiplas assinaturas/contas de cobrança, escolha o escopo com o maior volume de dados a exportar (preferencialmente a conta de cobrança principal).
2

Navegue até Exportações

No menu lateral do Cost Management, clique em Exports → botão + Create.

Não encontra "Exports"? Seu papel atual não tem permissão para criar exportações. Volte à premissa 2.
3

Selecione o template FOCUS

Na aba "Basics", localize o template "Cost and usage details (FOCUS)" → selecione → Next.

Não aparece? Clique em "Show more" para expandir as opções. Se ainda assim não aparecer, o contrato pode ser PAYG/MOSP — volte à premissa 5.
4

Configure os detalhes (aba Datasets)

CampoValor recomendado
Export prefixfocus-export ou nome do projeto/cliente
Type of dataCost and usage details (FOCUS) — preenchido pelo template
Dataset versionVersão mais recente disponível
FrequencyMonthly export of last month's costs
Para dados históricos, use "One-time export" com o período desejado. Para dados correntes, use "Monthly export".
5

Configure o destino (aba Destination)

Storage novo: Storage type = Azure blob storage → selecione subscription → resource group → crie o storage account (nome sem espaços, minúsculo) → região → container (ex: billing-focus) → directory (ex: azure/exports).

Storage existente: selecione subscription → storage account na lista → container → directory.

CampoValor para finops-focus
FormatCSV ✅ (recomendado)
CompressionGzip (arquivos grandes) ou None

File partitioning e Overwrite data já vêm habilitados por padrão — não é necessário alterar.

6

Revise e crie a exportação

Na aba "Review + create", confirme Type of data = Cost and usage details (FOCUS), o Storage Account e container → Create.

Status aparecerá como "Enabled". A exportação agendada rodará automaticamente no próximo ciclo.
7

Execute imediatamente (opcional)

Clique na exportação criada → Run now → aguarde "Em execução" → "Concluído".

Pode levar de minutos até 24h, dependendo do volume.
8

Exporte meses históricos (backfill)

Selecione a exportação → Export selected dates → escolha um mês por vez → Run. Repita para cada mês desejado.

Via portal, suporta até 13 meses. Para períodos maiores, é necessário usar a REST API do Azure.
9

Localize e baixe o arquivo gerado

Storage accounts → conta de destino → Containers → navegue até a pasta configurada:

[container]/[directory]/[export-name]/[YYYYMMDD-YYYYMMDD]/[RunID]/

Localize os arquivos .csv/.csv.gz e o manifest.json → Download.

Para volumes maiores, use o Azure Storage Explorer.

10

Valide o arquivo recebido

  • Extensão .csv ou .csv.gz, tamanho maior que 0 KB
  • Cabeçalho contém: BillingPeriodStart, ChargePeriodStart, EffectiveCost, ProviderName, ChargeDescription
  • Se particionado, o manifest.json está presente na mesma pasta

Windows (PowerShell):

Get-Content "arquivo.csv" -TotalCount 1
Campos diferentes dos esperados? O template pode ter sido "Actual"/"Amortized" em vez de FOCUS. Volte ao passo 3.

O GCP funciona de forma diferente dos demais provedores: o export FOCUS não gera arquivos diretamente — os dados chegam em uma tabela no BigQuery e precisam ser extraídos para o Google Cloud Storage (GCS) antes do download.

Status atual: o export FOCUS do GCP está em Preview (pré-disponibilidade geral), sujeito aos termos de pré-GA. Para uso em produção, considere esse contexto.
O processo envolve três camadas: Cloud Billing account (onde o export é habilitado) → Projeto GCP + BigQuery (onde os dados chegam, dataset imutável) → Google Cloud Storage (bucket para extração dos arquivos CSV).

Parte 2 — Manuseio da interface

Passo a passo de extração

O processo tem duas partes: habilitar o export FOCUS no BigQuery (passos 1–6) e depois extrair os dados do BigQuery para arquivos CSV no Google Cloud Storage (passos 7–10).

Fluxo completo: Billing → Billing export → Enable FOCUS export → dataset BigQuery imutável (gcp_billing_export_focus_<BILLING_ACCOUNT_ID>) → exportar para GCS → arquivo .csv.gz.
1

Acesse o console GCP e selecione o projeto correto

Faça login em console.cloud.google.com e, no seletor de projetos (topo), selecione o projeto dedicado para billing/FinOps — crie um novo se não existir.

Confirme que o billing está habilitado nesse projeto (premissa 4).

2

Acesse a página de Billing Export

Menu (☰) → Billing → selecione a billing account correta → menu lateral → Billing export → aba "BigQuery export".

Não encontra "Billing export"? Permissão insuficiente na billing account — volte à premissa 2.
3

Habilite o export FOCUS

Na aba "BigQuery export", localize "FOCUS usage cost" → clique em "Enable FOCUS export".

4

Configure o projeto e a localização do dataset

Projects: selecione o projeto onde o dataset será criado (o mesmo do passo 1). Se a BigQuery API não estiver ativa, clique em "Enable BigQuery API".

LocalizaçãoBackfill automático
US (multi-region)Sim — mês anterior
EU (multi-region)Sim — mês anterior
Região específicaNão
A localização do dataset não pode ser alterada após a criação. Escolha com cuidado, depois clique em "Save".
5

Aguarde a criação do dataset e a chegada dos dados

Nomenclatura gerada pelo Google:

Dataset: gcp_billing_immutable_<BILLING_ACCOUNT_ID>_<location>
Tabela:  gcp_billing_export_focus_<BILLING_ACCOUNT_ID>
Pode levar algumas horas até os primeiros dados aparecerem. Backfill do mês anterior (multi-region) pode levar até 5 dias para completar.
6

Confirme que os dados estão no BigQuery

Menu (☰) → BigQuery → Explorer → expanda o projeto → localize o dataset gcp_billing_immutable_... → tabela gcp_billing_export_focus_... → Preview.

Confirme os campos: BillingPeriodStart, EffectiveCost, ProviderName.

Dataset não aparece? Aguarde mais tempo (até 5h para os primeiros dados). Após 24h sem aparecer, revise permissões e se o export está habilitado.
7

Crie um bucket no Google Cloud Storage (GCS)

Menu (☰) → Cloud Storage → Buckets → Create. Nome (ex: billing-focus-export-[projeto]), mesma região do dataset (ou multi-region compatível) → mantenha o restante padrão → Create.

Se já existir um bucket disponível no mesmo projeto, pode reutilizá-lo com uma pasta/prefixo dedicado.

8

Exporte a tabela BigQuery para o bucket GCS

Opção A — console (períodos completos): na tabela gcp_billing_export_focus_... → ⋮ → Export → Export to GCS → informe o caminho do bucket, formato CSV, compressão GZIP → Export.

Opção B — SQL (filtrar por período):

EXPORT DATA OPTIONS(
  uri='gs://[bucket]/focus/[YYYY-MM]/*.csv.gz',
  format='CSV',
  compression='GZIP',
  overwrite=true,
  header=true
) AS
SELECT * FROM `[projeto].[dataset].gcp_billing_export_focus_[BILLING_ACCOUNT_ID]`
WHERE BillingPeriodStart >= '2025-01-01'
  AND BillingPeriodStart < '2025-07-01'
ORDER BY BillingPeriodStart;
9

Baixe os arquivos do bucket GCS

Menu (☰) → Cloud Storage → Buckets → navegue até a pasta exportada → selecione os .csv.gz → Download.

Via gsutil:

gsutil -m cp gs://[bucket]/focus/[YYYY-MM]/*.csv.gz ./focus-[YYYY-MM]/
gsutil -m cp -r gs://[bucket]/focus/ ./focus-local/
10

Valide os arquivos recebidos

  • Extensão .csv.gz, tamanho maior que 0 KB
  • Cabeçalho contém: BillingPeriodStart, ChargePeriodStart, EffectiveCost, ProviderName, ChargeDescription
  • ProviderName = Google

Linux/macOS:

zcat arquivo.csv.gz | head -1

Windows (PowerShell, após descompactar):

Get-Content "arquivo.csv" -TotalCount 1
Parte 3 — Suporte

Problemas frequentes

Bloqueios mais comuns e como resolvê-los.

Não encontro "Billing export" no menu ▾
Sem permissão na billing account. Solicite papel Billing Account Costs Manager ao administrador.
Opção "Enable FOCUS export" não aparece ▾
Papel insuficiente ou export já habilitado. Verifique se já existe um export ativo; senão, solicite Billing Account Costs Manager.
Dataset BigQuery não aparece após habilitar ▾
Ainda processando — pode levar horas. Aguarde até 24h; se persistir, verifique projeto e permissões do BigQuery.
Erro "Permission denied" ao exportar para GCS ▾
Sem permissão de escrita no bucket. Solicite papel Storage Object Creator no bucket GCS ao administrador.
Dados exportados mas sem campos FOCUS ▾
Exportou a tabela errada. Confirme que o dataset contém "gcp_billing_immutable" no nome e a tabela começa com "gcp_billing_export_focus_".
Backfill não chegou (dados só a partir de hoje) ▾
Dataset em região específica, não multi-region. Para backfill automático é necessário US ou EU; para outras regiões, exporte manualmente com filtro SQL por período.
Export desabilitado acidentalmente — dados perdidos? ▾
Se reabilitar no mesmo projeto/região, os dados anteriores ao disable continuam disponíveis. Se mudar projeto/região, os dados do período sem export são perdidos.

Parte 1 — Antes de começar

Premissas de acesso

A OCI funciona de forma diferente dos demais provedores: os relatórios FOCUS não precisam ser configurados. A Oracle os gera automaticamente a cada ~6 horas e os armazena em um bucket de Object Storage gerenciado pela própria Oracle — não pelo cliente.

O que você precisa fazer é apenas configurar uma policy IAM de cross-tenancy para que os usuários do seu tenancy possam ler esses arquivos a partir do tenancy da Oracle. Sem essa policy, o menu existe no console, mas os arquivos não ficam acessíveis para download.
1
Identifique seu tipo de tenancy e acesso
Tipo de acessoDescriçãoImpacto
Tenancy comercial (padrão)Conta OCI padrão, cobrança por usoRelatórios FOCUS disponíveis em todas as regiões comerciais
Tenancy Government / SovereignRegiões isoladas (OC2, OC3, OC4)FOCUS pode não estar disponível em todas as regiões soberanas
Tenancy de teste / Free TierTenancies não faturadosRelatórios de custo não disponíveis
Child tenancy (via Organization)Tenancy filho de uma OCI OrganizationCada tenancy tem seus próprios relatórios — sem consolidação automática
Acesse o OCI Console → menu superior direito → nome do tenancy → verifique se aparece "Paid" ou "Free Trial" no status da conta.
2
Policy IAM de cross-tenancy configurada

Este é o requisito mais importante e o bloqueio mais comum na OCI. Os relatórios ficam em um bucket da Oracle — sem esta policy, o download é negado.

A policy deve ser criada no compartimento raiz (root) do tenancy:

define tenancy usage-report as ocid1.tenancy.oc1..aaaaaaaaned4fkpkisbwjlr56u7cj63lf3wffbilvqknstgtvzub7vhqkggq
endorse group <nome_do_grupo> to read objects in tenancy usage-report
Não altere o OCID da primeira linha — é o identificador do tenancy Oracle que armazena os relatórios. Substitua apenas <nome_do_grupo> pelo grupo IAM do seu usuário.

Como verificar se já existe: Identity & Security → Policies → selecione o compartimento raiz → procure por uma policy com endorse group e tenancy usage-report.

Como testar se está funcionando: Billing & Cost Management → Cost and Usage Reports — se a lista de arquivos carregar (mesmo vazia para datas recentes), a policy está ativa.

3
Grupo IAM e permissões de usuário

Para a policy de cross-tenancy funcionar, seu usuário precisa pertencer ao grupo referenciado nela.

Verificar seu grupo: Identity & Security → Users → seu usuário → aba "Groups".

Verificar se o grupo tem a policy correta: Identity & Security → Policies → compartimento raiz → confirme que o nome do grupo no endorse group corresponde a um dos seus grupos.

Se seu usuário não pertence a nenhum grupo com a policy, acione o Tenancy Administrator para criar a policy com o grupo correto ou adicionar seu usuário ao grupo existente.
4
Permissão para acessar o menu Billing no console

Além da policy de cross-tenancy, acessar o menu "Billing & Cost Management" requer permissão de leitura em recursos de billing:

allow group <nome_do_grupo> to read usage-budgets in tenancy
allow group <nome_do_grupo> to read usage-reports in tenancy

Deve ser criada no compartimento raiz pelo administrador do tenancy.

Consegue ver o menu "Billing & Cost Management" mas não encontra "Cost and Usage Reports"? Provavelmente falta essa segunda policy.
5
Quem pode criar policies no tenancy

Apenas o Tenancy Administrator (membro do grupo Administrators) pode criar policies no compartimento raiz.

Como identificar: Identity & Security → Groups → grupo "Administrators" → veja a lista de membros.

Se você não é membro do grupo Administrators, acione um dos administradores listados para criar as policies necessárias.

Parte 2 — Manuseio da interface

Localização e download

Na OCI não há exportação para configurar — os relatórios FOCUS já existem no bucket da Oracle. O processo é apenas localizar e baixar.

Fluxo: Billing & Cost Management → Cost and Usage Reports → FOCUS Reports → YYYY → MM → DD → arquivo .csv.gz.
1

Acesse o OCI Console

Faça login em cloud.oracle.com com seu usuário OCI.

Certifique-se de estar na região home do tenancy — os relatórios ficam armazenados lá. Troque no seletor de região (canto superior direito) se necessário.
2

Navegue até Cost and Usage Reports

Menu (☰) → Billing & Cost Management → Cost and Usage Reports.

Não encontra "Billing & Cost Management"? Falta permissão — volte à premissa 4. Encontra o menu mas a lista não carrega? Falta a policy de cross-tenancy — volte à premissa 2.
3

Localize os relatórios FOCUS

Você verá dois tipos de conteúdo: relatórios no formato proprietário OCI (arquivos listados diretamente, ex: reports/cost-csv/YYYY-MM-DD-report-NNNNN.csv.gz) e os relatórios FOCUS, em estrutura de pastas.

  1. Expanda a pasta "FOCUS Reports"
  2. Expanda o ano desejado (ex: 2025)
  3. Expanda o mês (ex: 06)
  4. Expanda o dia (ex: 01)
É normal encontrar mais de um arquivo por dia. Histórico disponível por até 1 ano.
4

Baixe os arquivos para um período

Individual: navegue até a pasta do dia → menu de ações (⋮) ao lado do arquivo → "Download report".

Múltiplos dias: o console não suporta seleção em lote. Para volumes pequenos, repita manualmente; para volumes maiores, use a OCI CLI:

# namespace: bling · bucket: OCID do tenancy · prefixo: FOCUS Reports/YYYY/MM/DD/

oci os object list \
  --namespace-name bling \
  --bucket-name <seu-tenancy-ocid> \
  --prefix "FOCUS Reports/2025/06/01/"

oci os object bulk-download \
  --namespace-name bling \
  --bucket-name <seu-tenancy-ocid> \
  --prefix "FOCUS Reports/2025/06/" \
  --download-dir ./focus-junho-2025

O OCID do tenancy está disponível em Profile → Tenancy no canto superior direito.

5

Identifique quais arquivos baixar por período

Os relatórios são particionados por dia de uso (não por mês de faturamento, diferente de Azure/AWS) — é necessário baixar os arquivos de cada dia do período desejado.

Período desejadoPastas a baixar
Mês completo (ex: jun/2025)FOCUS Reports/2025/06/01/ até .../06/30/
Últimos 3 mesesTodas as pastas de dia dos 3 meses
Ano completoTodas as pastas diárias do ano
Para volumes grandes, use o comando bulk-download com o prefixo do mês/ano — muito mais eficiente que download manual.
6

Valide os arquivos recebidos

  • Extensão .csv.gz, tamanho maior que 0 KB
  • Cabeçalho contém: BillingPeriodStart, ChargePeriodStart, EffectiveCost, ProviderName, ChargeDescription
  • ProviderName = Oracle

Linux/macOS:

zcat arquivo.csv.gz | head -1

Windows (PowerShell, após descompactar):

Get-Content "arquivo.csv" -TotalCount 1
Arquivo com colunas como lineItem/referenceNo ou product/service? Você baixou o formato proprietário OCI, não o FOCUS. Volte ao passo 3 e expanda a pasta "FOCUS Reports".
Parte 3 — Suporte

Problemas frequentes

Bloqueios mais comuns e como resolvê-los.

Menu "Billing & Cost Management" não aparece ▾
Sem permissão de billing no IAM. Solicite ao Tenancy Administrator a policy allow group <grupo> to read usage-reports in tenancy.
Lista de relatórios não carrega ou dá erro de permissão ▾
Policy de cross-tenancy ausente ou incorreta. Solicite ao Tenancy Administrator a policy endorse group <grupo> to read objects in tenancy usage-report no compartimento raiz.
Vejo relatórios OCI proprietários mas não "FOCUS Reports" ▾
Pasta pode não aparecer se o acesso é muito recente. Aguarde até 24h; se persistir, verifique se o tenancy é faturado.
Arquivos com campos OCI em vez de FOCUS ▾
Baixou da pasta errada. Confirme que expandiu "FOCUS Reports" e não os arquivos listados na raiz.
Download pelo console é muito lento para vários meses ▾
Limitação do console para lote. Use a OCI CLI com bulk-download.
OCI CLI retorna erro 404 no bucket ▾
OCID do tenancy incorreto no comando. Verifique em Profile → Tenancy e corrija.
Arquivos com dados atrasados (lag de até 24h) ▾
Comportamento normal da OCI. Para dados do dia atual, aguarde o próximo ciclo de geração.
